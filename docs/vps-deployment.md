# VPS deployment (static Vite build)
Existing GitHub workflow publishes to GitHub Pages, not to a confirmed VPS. Before changing DNS or server configuration, identify current Nginx/Apache virtual host and document root. Back up current release and server config. Build a clean checkout using Node 20: npm ci && npm run build && node scripts/check-travel-pages.mjs. Deploy the complete dist directory (including assets, images, hotels, robots.txt and sitemap.xml) to a new release directory, test via staging, then switch the existing document root atomically. For Nginx, a static location typically uses try_files $uri $uri/ =404; preserve existing HTTPS and redirects. Serve JS with correct MIME type and do not route missing asset files to index.html. Verify homepage JS loads, real hotel galleries open, WhatsApp drafts populate, phone links work, all sitemap URLs return HTTP 200, and missing paths return 404. Keep previous release available for rollback. Submit sitemap in Google Search Console only after production verification. Confirm actual property identity, rates, photos and cancellation terms before advertising; do not treat outbound clicks as confirmed bookings. No VPS credentials or DNS are changed by this PR.

For Nginx, add `error_page 404 /404.html;` and `location = /404.html { internal; }` within the existing server block. Preserve HTTP status 404 (do not redirect to the homepage). GitHub Pages serves the root 404.html automatically. After publishing, test an intentionally invalid URL with curl -I and verify status 404 and the branded error body. The 404 page is excluded from sitemap and marked noindex.
